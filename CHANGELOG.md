# Changelog

All notable changes to this project are documented here.

The format follows [Keep a Changelog](https://keepachangelog.com/en/1.1.0/), and the project uses [Semantic Versioning](https://semver.org/spec/v2.0.0.html).

## [Unreleased]

### Security

- Host names that could not be real addresses (with spaces, commas or `*`, `?`, `!`, `|`, `@`, `[`, `]`, `#`) are refused when importing, connecting and trusting a host key. Before, a crafted name in an imported file could make "trust this host" add a key trusted for every host.
- Only a host key that a server actually presented can be trusted from the trust prompt.
- On Windows, file names from a server like `C:name` or `name:stream` are refused, so a download cannot land outside the chosen folder.
- Files edited in a local editor are copied to a private per-user folder (`$XDG_RUNTIME_DIR` or `~/.cache/setu/edit` on Linux) instead of the shared `/tmp`, and with no editor set, file types that would run instead of open (`.bat`, `.exe`, `.desktop`, `.command`, …) are refused.
- Pack snippets must be one line, so picking one can never run a command before you press Enter.
- Release builds: GitHub Actions pinned to commit SHAs, signing secrets never given to pull-request builds, an SBOM with every nightly, and daily dependency advisory checks. See `docs/security/phase1-review.md`.

### Added

- **Monitoring**: watch servers' CPU, memory, network traffic and disks live, with a two-minute history and alerts when a reading passes the limits you set. Setu reads Linux's own figures over SSH, so nothing is installed on the server. See `docs/user/monitoring.md`.
- **Monitoring alerts that reach you**: an alert only once a reading has stayed over its limit for a while you choose (2 minutes by default), so short spikes stay quiet; a desktop notification when an alert starts and when it clears; and a chart of CPU and memory over the last hour.
- **Monitoring details**: a watched host's busiest processes (CPU and memory), a bar for each CPU core, traffic on each network interface, and read and write speed for each disk.
- **Network tools**: check a port (with timings, even where ping is blocked), see a server's TLS certificate (trusted or not and why, when it expires, the whole chain), look up a name, ping a host and wake a computer with Wake-on-LAN. Run a check from your computer or through a saved host, to see a server's network the way the server does. See `docs/user/network-tools.md`.
- **Tunnels**: save SSH port forwards and start them with one click: a local port that reaches a database or admin page inside a server's network (like `ssh -L`), a SOCKS proxy for browsing through a host (like `ssh -D`), or a port on the server that reaches your computer (like `ssh -R`). Each tunnel shows whether it is running and how many connections it carries, can start when Setu opens, and reconnects by itself when the connection drops. Tunnels listen only on your own computer unless you choose otherwise. See `docs/user/tunnels.md`.
- Documentation: a **user guide** (`docs/user/`: getting started, every feature, keyboard shortcuts, settings and files, troubleshooting, with screenshots) and a **developer guide** (`docs/developer/`: building, architecture, IPC commands, testing, how-to recipes and how to keep the docs current). Start at `docs/README.md`.
- Extension points for builds of Setu that add their own hooks: an audit trail (SSH logins, file copies, finished workflow runs, refused commands), a command policy checked before each workflow step runs on a host, an access policy checked before every SSH login, a session recorder for SSH terminals (the terminal always says when a session is recorded, and keystrokes are never given to it), and a settings page of their own that can open a sign-in page in your browser. The open-source app ships with none, so nothing changes for you. See `docs/developer/extending.md`.

### Changed

- Development: unit tests for the desktop UI (Vitest, run in CI), a `justfile` with one command for each everyday task (`just check` runs everything CI runs), and git hooks (`just install-hooks`) that refuse commits with private keys or tokens, unformatted Rust, failing UI tests or a missing sign-off.

- A more restrained look: the Dark and Light themes now use neutral graphite and white surfaces with a blue accent instead of amber, and host cards, avatars, tags and buttons are quieter (one neutral avatar style, Connect as a secondary button, flat cards, smaller corners). High contrast is unchanged.
- A new look: a side rail for Hosts, Terminals, Keys, Snippets and the Vault; a slimmer host sidebar; rounded tabs; and one dialog layout (spacing, type sizes, a close button in the corner) for every dialog, built on shared design tokens across the Dark, Light and High contrast themes.
- The hosts sidebar's **Import** now offers PuTTY, MobaXterm, CSV and Ansible as well as `~/.ssh/config`.
- Files (SFTP) opens with Ctrl+Shift+E instead of Ctrl+Shift+F, which is now find, as in most terminals.
- Minimum supported Rust version is now 1.89 (needed by russh 0.65, which fixes RUSTSEC-2026-0495).
- The desktop app picks the terminal renderer itself (GPU on Windows and macOS, DOM on Linux, where WebGL showed new output one frame late under WebKitGTK); Settings → Terminal → **Renderer** can force either.
- The Files tab's server-side buttons are now icons (Edit, Permissions, New folder, Rename, Delete) with tooltips.

### Added

- **Prompt themes from other terminals**: Powerlevel10k, Oh My Zsh, Starship and Oh My Posh prompts now look right in Setu with any font. The Nerd Font icons and Powerline arrows are built in (no patched font to install), character widths follow Unicode 11 like zsh and bash so right-hand prompts and emoji line up, and SSH sessions ask the server for 24-bit colour. Settings → **Prompts** imports colour schemes from iTerm2 (`.itermcolors`), Windows Terminal (a scheme or a whole `settings.json`), Alacritty (`.toml`), base16/base24 (`.yaml`), kitty, Ghostty and Xresources, shows which prompt tools this computer already uses with lines to copy for the rest, and the palette's **Prompt check** draws every kind of glyph in a terminal. Turn it off in Settings → Features. See `docs/user/appearance.md`.
- **Work memory**: Setu can remember the commands you run (only on this device, off until you turn it on) and suggest automating work you repeat: the same commands in the same order become a workflow draft, one command run on several servers becomes a workflow for all of them (or their shared tag), and long commands you keep typing become snippets in the palette. Nothing typed at a password prompt is kept and secrets in commands are masked. Pause, delete single commands or wipe it at any time; **Copy summary** gives a Markdown summary of your routine work for a teammate or an AI assistant. Find it in Workflows → Memory; turn it off in Settings → Features. See `docs/user/work-memory.md`.
- Two more themes for the app and the terminal: **Ocean** (deep blue-green with a teal accent) and **Paper** (warm off-white with an amber accent), in the Classic and Studio layouts.
- Two new themes, Ember (warm charcoal with an amber accent) and Sandstone (soft paper tones with a teal accent), each with its own terminal palette and Studio skin. Pick them in Settings → Appearance or from the palette (`Theme`).
- **Workflows**: a visual builder for the jobs you run on servers. Draw steps that run a command on saved hosts (by name or `tag:`), wait for your approval, or pause; link them to run on success, on failure or always, and unlinked steps run at the same time. Run it to see each step light up, approve from the canvas, stop it, and read every host's output; past runs stay in history. Starts from templates (health check, rolling restart with approval, database backup). Workflows are TOML files you can keep in Git. Works in the Classic and Studio layouts; turn it off in Settings → Features. See `docs/user/workflows.md`.
- **Task board**: a **Board** tab in Workflows with To do, Doing and Done columns for ops work. Cards hold notes, a priority, a due date, the hosts they are about and the workflow that does the job, showing its last run; drag them between columns or move them with Alt+arrow keys. Saved to `board.toml` as you go. See `docs/user/workflows.md`.
- A second window layout, **Studio**, with a futuristic look (glass panels, neon edges, HUD-style labels), next to the current one (now called **Classic**): open sessions listed on the left with their connection state, a search box for hosts, commands and snippets in a new title bar, and a header over the terminal with Files, split, find and new-window buttons. Pick it in Settings → Appearance → **Layout**, from the command palette, or with the layout button; switching keeps your sessions running. See `docs/user/appearance.md`.
- Settings → **Features**: turn newer features (security keys, remote edit, paste guard) off or on. See `docs/developer/feature-flags.md`.
- Paste guard: pasting several lines into a shell that would run each line at once shows them and asks first.

- GPU-rendered terminal (WebGL) with font ligatures: a Renderer setting (Automatic, GPU, DOM), a Font setting, and ligatures on by default for fonts that have them; the status bar shows which renderer is in use. See `docs/user/appearance.md`.
- Files: **Pause**, **Resume** and **Retry** copies (one or all). Each file is written as `name.setu-part` and renamed when complete; resuming continues from the byte where it stopped, like `rsync --partial`. See `docs/user/files.md`.
- Files: edit a remote file in your own editor (**Edit** or F4). Every save is written back in place, keeping owner and permissions, and a save is refused if the server's copy changed meanwhile. See `docs/user/files.md`.
- Files: a permissions editor for remote items: read, write and execute for owner, group and others, the special bits, octal mode, user and group, optionally for everything inside a folder, with the matching `chmod`/`chown` shown. See `docs/user/files.md`.
- YubiKey and other FIDO2 security keys: make `ed25519-sk` and `ecdsa-sk` keys (optionally stored on the device or requiring the PIN each time), load keys stored on the device, and sign in with them through ssh-agent. See `docs/user/ssh-keys.md`.
- Hosts view: every saved host as a card with name, address, jump host, folder, tags and how many panes are open, grouped by folder, with search, tag filters, one-click Connect and Files, and keyboard control (Enter connects, E or F2 edits, arrow keys move). Open it from the rail or with "Go to hosts" in the palette. See `docs/user/hosts.md`.
- Command palette (Ctrl+Shift+P): one fuzzy search over commands, saved hosts, shells and profiles, open tabs, themes, keybinding profiles and snippets, with recent commands first and shortcuts shown. See `docs/user/terminal.md`.
- Themes: Dark, Light and High contrast for the whole app and the terminal, plus the terminal font size, in a new Settings dialog (Ctrl+,). Preferences are saved in `settings.json`.
- Keybinding profiles: Default, Vim (Ctrl+Space prefix, h j k l between panes) and Emacs (Ctrl+X 2, 3, o, 0; Alt+X for commands), with the pending prefix shown in the status bar. See `docs/user/terminal.md`.
- Tabs in their own window: drag a tab out of the window, or press Ctrl+Shift+N, and it moves to a new window with its running shells and scrollback.
- Shell profiles: a detected shell (including a WSL distro) with its own starting folder, arguments and environment variables, and a choice of shell for new tabs, in Settings → Shells.
- SSH key manager: lists keys in `~/.ssh` with fingerprint, passphrase and agent state; makes Ed25519, ECDSA or RSA keys (mode 0600, never overwriting); copies public keys; adds keys to ssh-agent. See `docs/user/ssh-keys.md`.
- Known hosts manager: lists, filters and forgets `known_hosts` entries, keeping `known_hosts.old`. See `docs/user/ssh-keys.md`.
- Secrets in terminal output are covered with a bar (cloud keys, tokens, JWTs, passwords in URLs and assignments, private key blocks), also in `less` and `vim`; copying still gives the real text. On by default. See `docs/user/terminal.md`.
- Copy and paste in the terminal with Ctrl+Shift+C and Ctrl+Shift+V.
- Host import from PuTTY (`.reg` export), MobaXterm (`.mxtsessions`), Termius or any CSV, and Ansible inventories (INI and YAML), keeping folders; passwords are never read. A jump-host map shows which hosts are reached through which bastions. See `docs/user/hosts.md`.
- Roles and packs: a first-launch role picker turns on the built-in system administrator pack of 25 snippets; snippets are typed into the terminal from the palette, never run. Settings → Packs installs a pack from a local `.json` file after showing what it asks for. See `docs/user/packs.md`.
- Tabs come back after a restart: Setu reopens your tabs with their splits, divider positions and focused pane. Local panes start a fresh shell; SSH panes wait for Enter, then reconnect without the dialog unless a password, passphrase or host-key check needs you, and split SSH panes log in once. Saved in `session.json` (no secrets; mode 0600 on Unix), which `setu paths` now lists. See `docs/user/terminal.md`.
- Split panes: split a terminal tab side by side (Ctrl+Shift+D) or stacked (Ctrl+Alt+Shift+D), as often as you like; drag the dividers to resize, move focus with Alt+Arrow keys, and close a pane with Ctrl+Shift+W. Splitting an SSH pane opens another shell over the same connection, with no new login. See `docs/user/terminal.md`.
- Find in a terminal's scrollback (Ctrl+Shift+F): matches highlighted as you type, a match counter, next and previous, and match case, whole word and regular expression options. See `docs/user/terminal.md`.
- Vault: **Unlock automatically on this computer** keeps the vault key in the macOS Keychain, Windows Credential Manager or the Linux Secret Service, so the vault opens at start-up and after the idle timeout without the master password. Off by default; **Lock now** still requires the password, and turning it off deletes the stored key. See `docs/user/vault.md`.
- Nightly builds: a scheduled workflow builds the desktop app (`.dmg`, `.msi`, `-setup.exe`, `.AppImage`, `.deb`, `.rpm`) and the `setu` CLI for macOS (universal), Windows and Linux, and publishes them as the rolling `nightly` pre-release with `SHA256SUMS` and GitHub build-provenance attestations. macOS signing and notarization and Windows Authenticode switch on when their secrets are added; until then macOS builds are ad-hoc signed. See `docs/developer/releasing.md`.
- `setu` command line (`setu-cli`): `setu doctor` checks private-key permissions and passphrases, ssh-agent and the keys it holds, `~/.ssh/config` permissions and missing `IdentityFile`s, `known_hosts`, and Setu's saved hosts and vault file, with a fix for each problem (`--json` for scripts; exit code 1 when something blocks SSH). `setu hosts` lists and searches saved hosts, and `setu hosts import` previews or saves hosts from `~/.ssh/config`. See `docs/user/cli.md`.
- Files tabs (SFTP): two panes, your computer and an SSH host, with upload and download by button or drag and drop, folder copies, a transfer queue with progress, speed and cancel, and new folder, rename and delete on the host. Opens from an SSH tab (Ctrl+Shift+E) or from a host's ⇅ button, reusing that connection. See `docs/user/files.md`.
- Encrypted vault (`setu-vault`): saves SSH passwords and key passphrases under a master password (Argon2id + XChaCha20-Poly1305), locks itself after 15 minutes idle, and fills them in when you connect, so saved hosts connect without asking. "Save in vault" in the connect dialog, a vault indicator in the status bar, and a vault dialog to remove secrets, lock, or change the master password. See `docs/user/vault.md`.
- Saved hosts (`setu-hosts`): a hosts sidebar with folders, tags and search; double-click (or Enter) to connect; add, edit and delete hosts. Hosts are stored in a plain `hosts.toml` without secrets (see `docs/user/hosts.md`). **Import** brings in hosts from `~/.ssh/config`, following `Include` and OpenSSH's matching rules. Ctrl+Shift+H shows the sidebar and focuses search.
- SSH connections accept a ProxyJump chain (`a,b`), and an empty user means your local user name, as in OpenSSH.
- SSH connections (`setu-ssh`, built on russh): strict host-key checking against `~/.ssh/known_hosts` with a fingerprint trust prompt and a hard stop on changed keys; ssh-agent, default `~/.ssh` keys, key files with passphrase, and password auth; ProxyJump through a bastion; interactive shells with resize. The desktop app adds a "New SSH connection" dialog (Ctrl+Shift+O) and SSH tabs.
- Desktop app (Tauri 2 + xterm.js): opens your default shell on first launch, terminal tabs for any detected shell (shell picker), close/switch tabs with Ctrl+Shift+T, Ctrl+Shift+W and Ctrl+Tab, resizing that follows the window, and a status bar with shell and size.
- `setu-pty`: detects local shells (bash, zsh, fish, sh, PowerShell, Windows PowerShell, cmd and WSL distros) and runs them in a pseudo-terminal with input, output streaming, resize and exit status.
- Project foundation: community files, Cargo workspace with `setu-core`, CI on macOS, Linux and Windows, and the first architecture decision records.
